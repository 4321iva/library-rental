# Library Rental

Практична 1 курсу «ERP-CRM системи». Модуль `library_rental` для Odoo 19 Community. Версія практичної 1 позначена тегом `practice-1`. Середовище використовує Python 3.12 та PostgreSQL 16 у Docker. Dockerfile отримує зафіксовану ревізію вихідного коду Odoo 19 з GitHub.

## Що згенерував AI

До ChatGPT був запит із двома методичками й чеклістом: «ось лаби які треба зробити ти зробиш і поясниш мені […] що і як мені треба зробити щоб викладач це побачив». Для каркаса у вкладеному завданні було уточнення: «згенеруйте каркас нового модуля custom_addons/library_rental: __manifest__.py, порожні пакети models/, views/, security/». За цими вимогами ChatGPT підготував каркас, маніфест, файли Docker і початкові коміти.

## Що перевірено та виправлено вручну

Під час підготовки асистентом перевірено, що встановлення починається з `base`, версія має формат `19.0.x.x.x`, ліцензія вказана і кореневий `__init__.py` імпортує `models`. Каталоги `views` та `security` збережено у Git через `.gitkeep`. Поле `application` дає змогу знайти модуль у списку програм.

Для власної перевірки відкрийте маніфест у редакторі, звірте ці поля, внесіть свою правку та запишіть тут, що саме змінили. Результат перевірки в Copilot можна зафіксувати поруч.

## Практична 2

Версія з моделями, екранами та даними позначена тегом `practice-2`. У меню «Бібліотека» є книги, примірники, читачі та видачі. Після встановлення або оновлення модуля додаються 3 книги, 6 примірників, 2 читачі та 3 видачі. Приклади лежать у `data/example_data.xml` і завантажуються також у базу, створену без стандартних демо-даних Odoo.

### Структура зв’язків

| Зв’язок | Тип | Навіщо |
| --- | --- | --- |
| `Copy.book_id` → Book | Many2one | Кожен фізичний примірник належить одній книзі. |
| `Book.copy_ids` → Copy | One2many | Зворотний список усіх примірників книги через `book_id`. |
| `Loan.copy_id` → Copy | Many2one | Видача стосується конкретного інвентарного номера. |
| `Copy.loan_ids` → Loan | One2many | Історія видач одного примірника через `copy_id`. |
| `Loan.member_id` → Member | Many2one | Кожну видачу оформлено на одного читача. |
| `Member.loan_ids` → Loan | One2many | Історія видач читача через `member_id`. |

Для читача обрано окрему модель `library.member` з ім’ям та унікальним номером квитка. Для цього завдання достатньо цих двох полів. Делегування до `res.partner` мало б сенс для повторного використання контактів. Книги, примірники та читачі захищені від видалення, якщо на них посилається обов’язкове поле Many2one. Для всіх трьох таких полів використано `ondelete="restrict"`.

Назва, автор і номер квитка у формі видачі підтягуються через `related`. Історія видач дозволяє кілька записів на один примірник. Обмеження на одну активну видачу віднесено до практичної 3 за методичкою.

### Що згенерував AI для практичної 2

Той самий запит включав завдання «реалізувати […] в Odoo: чотири моделі, базові views, перші операції через ORM (create, write, search, домени)». ChatGPT підготував моделі у чотирьох файлах, списки й форми, меню, права доступу для внутрішніх користувачів, демо-дані та скрипт виконання ORM-запитів.

### Що перевірено та виправлено вручну в практичній 2

Під час рев’ю асистентом перевірено зв’язки `Copy.book_id`, `Loan.copy_id` та `Loan.member_id`: усі обов’язкові, з явним `ondelete="restrict"`. Поля `due_date` і `loan_date` обов’язкові, а `return_date` можна заповнити під час повернення. Поле для показу книги у формі видачі спрощено до пов’язаного текстового `book_name`: окремий ідентифікатор книги вже доступний через примірник. Для списків використано тег `list` Odoo 19. Після власної перевірки тут можна вказати додаткові зміни.

### Чотири операції ORM

`scripts/orm_demo.py` демонструє пошук книг автора, підрахунок вільних примірників «Кобзаря», пошук прострочених видач та створення і закриття однієї видачі. Запуск із кореня проєкту після встановлення або оновлення модуля:

```powershell
docker compose exec -T odoo sh -c "python3 /opt/odoo/odoo-bin shell -d lab_odoo --no-http < /mnt/workshop/scripts/orm_demo.py" | Tee-Object -FilePath orm-log.txt
```

Скрипт відкочує тимчасову видачу в кінці, тому демонстрацію можна повторити.
